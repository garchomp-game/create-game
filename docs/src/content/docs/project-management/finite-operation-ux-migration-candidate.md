## 判断したい一件

**「一戦内で育ち、敵の要を倒して作戦を終える」を、有限作戦の第一検証候補にするか。**

推薦は検証方向としての採用です。「包囲反転」という製品の北極星や、一戦内成長・
戦闘力を持ち越さない契約を捨てる判断ではありません。最初に確かめる体験と順序を
限定し、11分目を初回の試作から外します。

未検証なのは、成長を使って要を攻め、自分で一戦を終えた満足と再挑戦理由が
生まれるかです。既存Commanderの効果、短い局面の理解、有限作戦全体の面白さ、
正式公開の採用は、それぞれ別の証拠と判断を必要とします。

採用 / 修正 / 保留 / 棄却の結論は未記入です。人間観察の実施・成立も主張しません。

## S01の開始・受け渡し・正式完了

### #143が先に固定する仕様

S01はデータ追加だけとは見積もりません。現行clearConditionにはCommander撃破で
作戦完了する条件がなく、ExpeditionControllerは最終遠征のdeck / actsを固定参照します。
#143は次のCandidateSpecを埋め、終端ownerと変更可能ファイルを固定します。

- 作戦の問い、初期装備、強化取得と利用機会、敵配置・進行・期限の時計。
- 勝利、死亡、timeout、撤収、中断、同frame競合の優先順、二重終端防止。
- 専用mode / stage / profile、必要な型拡張、既存Controllerへの限定接続。
- 入口、目標、結果VM、戻り先、retry初期化、固定seedと通常新seedの区別。
- 固定SHA、Pulse / Spreadの条件、対象QA、匿名観察票、rollback。

記録隔離は**専用mode / stage / profileと、modeの`recordPolicy: none`**を第一案とします。
stage / profileだけの追加では隔離できません。候補clear・unlock・途中run復元は保存せず、
#139の`story / story-intro`完了と混ぜません。既存profile ID、設定、履歴、PBを保護します。

非記録runではrunLifecycleがdiscardされるため、既存の結果表示をそのまま使うと
保存エラーになる経路があります。S01が「保存しない正常終了」と「保存試行の失敗」を
区別するVMを所有し、#142のViewが独自に推測しません。
`game.over`だけで勝敗を判定せず、Commanderのkilledとretiredも分離します。
**CandidateSpec未完のまま、S01を起票・runtime実装へ進めません。**

### open・非activeで視覚へ渡せる狭い例外

次が揃い、PMが視覚展開可と判断した場合だけ、S01を`candidate-ready`として渡す案です。
この語は受け渡し判定であり、ラベル新設や正式公開採用を意味しません。

1. 固定candidate SHA、source / build識別、実行方法、変更ルール、残課題。
2. 対象QA、記録非介入、既存mode回帰、独立監査の重大指摘解消。
3. 有限作戦を対象とした短い人間観察と、攻め方・決着・再挑戦・未観測の記録。
4. PMの受け渡し判断と、#141が比較元にする固定SHA。

S01は**openの非active採用待ち**へ移し、#141だけを次の一件にできます。
同時writerは増やさず、監査済み元SHAを変更せず、新candidateで視覚を適用します。
人間観察がなければ`awaiting-human`で、本格的な視覚制作へ進みません。
S01不成立・保留の場合も、#141へ自動進行せずPMが範囲を再判断します。

#81の統合採用 / 修正 / 保留 / 棄却で最終状態を決めるまで、S01を最終完了として
closeしません。修正・保留なら残件と再開条件を維持します。必要な進行保存が未設計なら
公開採用を保留します。この例外はD01採用時にqueue・運用2文書へ同時同期します。

## 人間観察と比較の境界

#144の局面観察、S01の短い有限作戦観察、#81の正式統合採否を混ぜません。
同じ参加者を複数セルで完全初見へ戻さず、自動greenを楽しさの証拠にしません。

#81は初心者2名・経験者2名、各2runを探索的最低条件として維持します。
S01を初回主導線に選ぶ場合、初心者を別参加者の次の2セルへ最低1名ずつ割り当てます。

- N-operation: 無誘導のタイトル → 初期作戦 → 作戦選択 → 有限作戦全体。
- N-endless: 無誘導のタイトル → 初期作戦 → 同武器Endlessの死亡または90秒。

教材・分類質問は各無誘導経路の後に置きます。2回目を初見に数えず、セル別露出人数を
示し、各1名の差から経路の優劣を断定しません。経験者は既存modeとS01を区別します。
EXの質問はONかつ該当能力へ露出したrunだけとします。

killed / retired、未到達、未露出、機会なし、機会あり未実行、失敗を別記録にします。
機会あり未実行を評価可能な分母から除外せず、任意の再挑戦をしないことを入力失敗に
しません。原因理解・面白さ・実際の再開始も別々に記録します。

#80では既存Endless / Final Expeditionの回帰と、S01の視覚前後比較を分けます。
後者の基準は#141着手前のS01 SHAであり、新しい勝利条件を持つS01全体へ
元mainとのsimulation同値を要求しません。

1. 起票直前にopen数、P0数、next、writer、権限を読み直す。2026-10-05は11件からD01（#146）一件だけを起票し、12件になった。
2. D01はP1 / queuedで起票済み。既存P0を増やさず、方針判断と必要な正本・Issue同期を終えてからcloseする。

## 非スコープ、rollback、再開チェック

本候補はdocs-onlyです。runtime、作戦の具体的な長さ・本数、敵・武器・XP・密度、
既存勝利条件、profile schema、記録を変えません。途中セーブ、恒久戦闘力、素材周回、
隠れた難度補正、汎用Controller、全UI刷新、EX既定ON、11分目実装を開始しません。

保留・棄却なら、本ページの状態と理由を更新し、現行キューを維持します。
既に実装した#138等の別候補やユーザーデータは戻しません。正式移行後にrollbackが
必要なら、保存した旧本文・判断履歴から依存だけを復元する新差分として扱います。

再開前の確認:

- [ ] D01の採用 / 修正 / 保留 / 棄却と、その判断範囲を記録した。
- [ ] 未提供参照の扱い、live SHA、対象Issue本文、open / P0 / nextを再確認した。
- [ ] 単一writer、所有ファイル、最小QA、Git / 外部書込権限を固定した。
- [ ] 採用する場合、正本とIssueの旧依存を置換し、循環・自動#145・未解決リンクをなくした。
- [ ] S01受け渡し条件と#141開始条件、#81最終採否が運用3正本で一致した。
- [ ] docs差分・リンク・Starlight build・独立した依存監査を完了した。
- [ ] runtimeへ進む対象一件のGoal ContractがReadyである。S01には完成した#143仕様がある。

このチェックが未完なら、移行候補の作成と、移行の採用・実施・完了を区別して報告します。
新方針を必要としない既存契約内のbug fixは、この移行全体の完了とは別に判断します。
